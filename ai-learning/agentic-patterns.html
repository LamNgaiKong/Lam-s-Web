    Antonio Gulli（Google 杰出工程师）著，21 种智能体设计模式 + 7 个附录的分章速览；基于 Jimmy Song 社区中文翻译提炼，用于快速建立模式地图。

    全书概述

    本书是智能体（Agent）设计模式的实战指南，系统讲解 21 种设计模式 + 7 个附录。配套 GitHub 仓库提供全书 PDF（424 页）与各章 Notebook 供动手学习，作者版税全部捐赠给 Save the Children。

    全书结构（四部分）：

    • 核心模式（第 1–7 章）：提示链、路由、并行化、反思、工具使用、规划、多智能体协作
    • 进阶模式（第 8–11 章）：记忆管理、学习与适应、MCP、目标设定与监控
    • 生产模式（第 12–14 章）：异常处理与恢复、人机协同、知识检索（RAG）
    • 企业模式（第 15–21 章）：A2A、资源感知优化、推理技术、护栏与安全、评估与监控、优先级排序、探索与发现
    第一部分 · 核心模式（第 1–7 章）智能体的基础构件

    第1章 提示链 Prompt Chaining

    核心思想：将复杂任务分解为顺序执行的子任务，前一步输出作为下一步输入，以提升可靠性。

    关键要点：以 JSON 等结构化输出保证精度；各步骤可集成外部工具/API；LangChain/LangGraph 负责状态管理。

    适用场景：多步推理、数据抽取与内容生成等单次提示难以胜任的任务。

    第2章 路由 Routing

    核心思想：为智能体引入条件逻辑，按请求动态选择处理路径。

    关键要点：路由器可基于 LLM、嵌入、规则或 ML 模型实现；LangGraph 与 Google ADK 等框架均支持。

    适用场景：客服等需按意图分流的场景与复杂工具调度。

    第3章 并行化 Parallelization

    核心思想：将相互独立的子任务并行执行，显著降低整体延迟。

    关键要点：识别无依赖任务并行处理、结束后合并结果；可用 LangChain 的 RunnableParallel 或 Google ADK 的 ParallelAgent 实现。

    适用场景：多源研究、并发 API 调用、多模态分析与 A/B 测试。

    第4章 反思 Reflection

    核心思想：以"生成—批判"反馈循环让智能体自我纠错。

    关键要点：采用生产者/批评者双智能体模型；可用 LangChain LCEL 迭代优化或 ADK SequentialAgent 管道实现。

    适用场景：对输出质量要求高的任务，需权衡延迟与成本增加。

    第5章 工具使用（函数调用）Tool Use

    核心思想：通过函数调用将 LLM 与外部系统连接，突破静态训练数据的局限。

    关键要点：定义工具后由 LLM 决定调用并生成 JSON 参数，框架执行并将结果回填上下文；支持 LangChain、CrewAI、ADK。

    适用场景：实时数据获取、数据库/API 交互、代码执行与系统控制。

    第6章 规划 Planning

    核心思想：让智能体将复杂目标拆解为可执行步骤，并动态生成与迭代调整计划。

    关键要点：CrewAI、Google DeepResearch 与 OpenAI API 展示了规划能力。

    适用场景：多步骤工作流自动化。

    第7章 多智能体协作 Multi-Agent Collaboration

    核心思想：将复杂目标分解给多个专职智能体，通过协作完成整体任务。

    关键要点：按顺序、并行或层级结构划分角色；CrewAI 与 Google ADK 支持实现；通信协议保证一致性。

    适用场景：复杂研究、软件开发与内容生成等模块化可扩展任务。

    第二部分 · 进阶模式（第 8–11 章）状态、学习与协议

    第8章 记忆管理 Memory Management

    核心思想：智能体需要短期上下文与长期持久化记忆，才能实现连贯个性化交互。

    关键要点：长期记忆靠向量库语义检索；ADK 以 Session/State/MemoryService 管理状态；LangGraph 用缓冲与存储跨会话保存。

    适用场景：多轮对话与跨会话个性化服务，可用 Memory Bank 自动抽取事实。

    第9章 学习与适应 Learning and Adaptation

    核心思想：智能体通过强化学习、LLM 与进化方法自我进化，减少人工干预。

    关键要点：涉及强化学习（RL）、SICA 与 AlphaEvolve 等学习与进化途径。

    适用场景：需要持续自我改进的动态环境任务。

    第10章 模型上下文协议 Model Context Protocol (MCP)

    核心思想：MCP 以开放标准与客户端-服务器架构，实现 LLM 与外部系统的标准化交互。

    关键要点：支持动态发现工具与资源；优于专有函数调用，促进互操作性；底层 API 需具备确定性特性。

    适用场景：复杂智能体系统集成，优先采用以解决多样化集成难题。

    第11章 目标设定与监控 Goal Setting and Monitoring

    核心思想：为智能体设定目标并监控进度，使其具备方向感与自我评估能力。

    关键要点：规划生成子目标步骤；采用"生成-评估-改进"循环；以 LLM 判断目标达成；多智能体分离评审增强客观性。

    适用场景：复杂任务的可靠执行，需注意 LLM 幻觉并辅以人工测试（示例用 LangChain 迭代优化 Python 代码）。

    第三部分 · 生产模式（第 12–14 章）可靠性、人机协同与知识

    第12章 异常处理与恢复 Exception Handling and Recovery

    核心思想：通过检测、处理与恢复机制，构建能应对故障的健壮智能体。

    关键要点：错误检测涵盖日志、重试与备用方案；恢复策略包括回滚与自我修正。

    适用场景：客服、金融交易等需高可靠性的真实环境部署。

    第13章 人类参与环节 Human-in-the-Loop

    核心思想：将人类判断融入 AI 流程，确保高风险场景决策合乎伦理与安全。

    关键要点：提供 escalate_to_human 等升级工具；以人类反馈驱动学习；复杂任务保留人工监督。

    适用场景：金融、法律与内容审核等对准确性、伦理要求高的领域。

    第14章 知识检索（RAG）Knowledge Retrieval

    核心思想：检索外部数据增强 LLM 回答，提升准确性与时效性。

    关键要点：涵盖嵌入、向量数据库、GraphRAG 与 Agent RAG 验证等技术。

    适用场景：企业搜索、客户支持与动态知识任务。

    第四部分 · 企业模式（第 15–21 章）规模化与治理

    第15章 智能体间通信 Inter-Agent Communication (A2A)

    核心思想：A2A 协议实现跨框架智能体间的互操作与协作。

    关键要点：以 Agent Card 发现智能体；基于 HTTP/JSON-RPC 通信；支持多模态交互。

    适用场景：多智能体编排，如 ADK 与 LangChain 的集成。

    第16章 资源感知优化 Resource-Aware Optimization

    核心思想：智能体动态管理计算、时间与财务资源，平衡效率与成本。

    关键要点：按复杂度路由不同 LLM（如 Flash/Pro）；优雅降级与回退；优化 Token 预算与上下文剪枝；批判智能体重估质量。

    适用场景：控制 API 成本、延迟敏感或边缘部署的应用。

    第17章 推理技术 Reasoning Techniques

    核心思想：显式化推理过程，用增加思考时间换取求解准确性与健壮性。

    关键要点：CoT 逐步推理、ToT 多路径探索与回溯纠错；ReAct 以思考-行动-观察循环动态调整；合理分配算力可让小模型媲美大模型。

    适用场景：数学求解、代码调试等需多步逻辑与自我纠错的任务。

    第18章 护栏与安全模式 Guardrails / Safety Patterns

    核心思想：护栏是确保智能体安全合规、防止有害输出的多层防御机制。

    关键要点：输入验证与输出过滤（如 CrewAI 的 Pydantic 校验）；用 Gemini Flash 等轻量模型预筛查；最小权限与可观测日志。

    适用场景：客服、法律/医疗助手与社交审核等需防有害输出的场景。

    第19章 评估与监控 Evaluation and Monitoring

    核心思想：通过持续评估与监控保证智能体的性能、效率与合规性。

    关键要点：追踪准确率、延迟与 Token 用量；采用 LLM 评审与轨迹分析；ADK 支持自动化测试；以正式合同模式增强问责。

    适用场景：生产环境需 A/B 测试与漂移检测，高风险场景用结构化合同明确交付标准。

    第20章 优先级排序 Prioritization

    核心思想：智能体按紧急性、重要性等标准动态排序任务，聚焦关键目标。

    关键要点：评估标准含紧急性与依赖关系；评分体系或 LLM 推理评估；队列/调度逻辑确定顺序；支持动态调整优先级。

    适用场景：自动化客服、云资源调度与金融交易等资源有限且目标冲突的场景。

    第21章 探索与发现 Exploration and Discovery

    核心思想：智能体主动探索未知领域，生成新知识。

    关键要点：Google Co-Scientist 多智能体协作；Agent Laboratory 自动化科研流；模拟人类评审机制。

    适用场景：科学研究、市场趋势发现与创意内容生成等开放复杂领域。

    附录（A–G）中文翻译站实际收录 7 个附录

    附录A 高级提示工程技术

    核心思想：详解提示工程，通过优化交互提升智能体的推理精度与执行可靠性。

    关键要点：涵盖 CoT、ReAct 及结构化输出等高级技术。

    适用场景：需要精细控制模型行为的各类智能体应用。

    附录B 智能体交互：从 GUI 到现实世界环境

    核心思想：智能体经 ACI（Agent-Computer Interaction）与 GUI 及物理环境交互，实现复杂自动化。

    关键要点：涉及 ChatGPT Operator、Project Mariner 等工具；支持浏览器控制与现实感知；催生 Vibe Coding 开发新范式。

    适用场景：桌面/浏览器自动化与真实世界任务执行。

    附录C 智能体框架速览

    核心思想：对比主流智能体框架，指导按需选型。

    关键要点：比较 LangChain、LangGraph、ADK 与 Crew.AI 等框架；按线性或循环流程需求选择。

    适用场景：项目启动时的框架选型决策。

    附录D 使用 AgentSpace 构建智能体

    核心思想：AgentSpace 以无代码 UI 与知识图谱，帮助企业构建具自主推理能力的智能体。

    关键要点：集成多服务、自定义提示词，基于 A2A 协议协作。

    适用场景：希望将 AI 嵌入日常工作的非技术团队，提升决策效率与生产力。

    附录E 命令行上的智能体

    核心思想：CLI 智能体把命令行升级为智能工作空间。

    关键要点：Claude CLI 擅长复杂重构；Gemini CLI 支持多模态与云端；Aider 面向 Git 驱动编辑；Copilot CLI 集成 GitHub。

    适用场景：代码重构、Git 驱动编辑等终端内开发工作流。

    附录F 探秘引擎：智能体推理引擎的内部解析

    核心思想：LLM 作为推理引擎，以结构化"思维链"过程模拟逻辑演绎。

    关键要点：解析提示、检索模式，以概率化 token 预测模拟推理。

    适用场景：理解智能体内部机制、优化提示与模型选择。

    附录G 编程智能体

    核心思想：Vibe Coding 开启创新，结构化智能体团队进一步提升生产力。

    关键要点：Scribe、Reviewer 等角色分工；以人类为主导编排；精确上下文简报。

    适用场景：需要质量把关与人类主导的编程协作场景。
